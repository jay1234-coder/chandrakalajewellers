# Database migration guide — MySQL/MariaDB → PostgreSQL

**Do not run this against InfinityFree production.** Work on a local copy or a new Postgres database only.

## Source

- Engine: MariaDB 11.4 (InfinityFree) / local XAMPP MySQL
- Name: `if0_38635607_cjdb`
- Dump in repo: `if0_38635607_cjdb.sql` (15 Aug 2026)
- Live PHP also auto-ALTERs columns (`copper_rate`, `tags`, reservation fields). Prefer a **fresh dump** before cutover.

## Target

- PostgreSQL 15+ (Neon / Vercel Postgres recommended)
- Schema files:
  - `database/schema.sql` — core tables used by the new API
  - `database/migrations/002_php_parity_tables.sql` — remaining PHP tables
  - `database/seed.sql` — **settings and rates only**; do not treat jewellery INSERTs as production data

## Type mapping

| MySQL | PostgreSQL |
|-------|------------|
| `INT UNSIGNED AUTO_INCREMENT` | `SERIAL` / `INT GENERATED BY DEFAULT AS IDENTITY` |
| `TINYINT(1)` | `BOOLEAN` (map 0/1) |
| `DATETIME` / `TIMESTAMP` | `TIMESTAMPTZ` (store IST as `+05:30` or UTC and convert in app) |
| `ENUM(...)` | `VARCHAR` + `CHECK` |
| `DECIMAL(p,s)` | `NUMERIC(p,s)` |
| `TEXT` | `TEXT` |
| MyISAM / latin1 | InnoDB equivalent is irrelevant; import as UTF-8 |

## Charset

`jewellery_items` and `products` in the dump are **latin1**. Convert on export:

```bash
mysqldump --default-character-set=utf8mb4 --single-transaction if0_38635607_cjdb > cj_utf8.sql
```

Or convert in Postgres after load with `convert_from` / `convert_to` if mojibake appears (Gujarati names, emoji in descriptions).

## Password hashes

- PHP: `password_hash(..., PASSWORD_DEFAULT)` → `$2y$10$...`
- Node `bcryptjs`: compare after replacing prefix `$2y$` with `$2a$` (same bcrypt digest).
- **Do not re-hash** with a temporary password. If compare fails for a user, use a reset flow.

## Tables to copy (order)

1. `admin_users`, `customers`
2. `rates`, `manual_rates`, `site_settings`
3. `jewellery_items` (disable FK to orders while loading)
4. `jewellery_item_images`, `products`, `product_reviews`
5. `orders`, `order_items`
6. `payments` (legacy)
7. `abandoned_carts`
8. `admin_remember_tokens`, `admin_login_attempts`, `admin_activity_log`
9. `internal_messages`, `cron_meta`
10. Push + visitor tables (optional if PWA analytics move later)

Reset sequences after INSERT with explicit IDs:

```sql
SELECT setval(pg_get_serial_sequence('jewellery_items','id'), (SELECT MAX(id) FROM jewellery_items));
```

Repeat for every SERIAL table.

## Business rules to keep

- One physical piece: `is_sold_out` + `reserved_order_id` + `reserved_until`
- Reservation TTL: 24 hours
- `cached_price` is derived; refresh after rate changes
- `products` is the **design catalogue**, not shop stock
- Feature flags live in `site_settings`, not env (except DB/JWT/Razorpay secrets)

## What not to do

- Do not `DROP DATABASE` on InfinityFree.
- Do not load `database/seed.sql` jewellery rows over real IDs (seed rewrites names/categories).
- Do not commit `.env` or dump hashes into public docs.

## Verification queries (after import)

```sql
SELECT COUNT(*) FROM jewellery_items;
SELECT COUNT(*) FROM products;
SELECT gold_rate, silver_rate, silver_925_rate, making_charges_percent FROM rates ORDER BY updated_at DESC LIMIT 1;
SELECT username, role FROM admin_users;
SELECT id, name, phone FROM customers;
SELECT status, COUNT(*) FROM orders GROUP BY status;
```

Compare counts with MySQL before switching the Flutter API to Postgres.
